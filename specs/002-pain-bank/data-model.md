# Data Model: Pain Bank

## Stored entities (Supabase Postgres)

### participants

| column | type | constraints |
|---|---|---|
| id | uuid | PK, client-generated |
| name | text | not null; unique on `lower(name)` |
| created_at | timestamptz | not null, default now() |

- RLS enabled, no anon policies — only the service-role key (server routes) reads/writes.
- `id` is generated by the browser (`crypto.randomUUID()`) at signup and stored in localStorage; it is not a secret (the participant list, including ids, is the device-recovery mechanism).

### entries

| column | type | constraints |
|---|---|---|
| id | uuid | PK, client-generated — the idempotency key |
| participant_id | uuid | not null, FK → participants(id) |
| day | date | not null (Sydney-local challenge date) |
| exercise | text | not null (validated against the closed ExerciseId union server-side) |
| count | int | not null, check: between −500 and 500 and ≠ 0 |
| created_at | timestamptz | not null, default now() |

- Indexes: `(day)`, `(participant_id, day)`.
- Append-only signed deltas. Corrections are negative rows; nothing is updated or deleted.
- Insert path is `upsert(..., { ignoreDuplicates: true })` on `id`: a retried POST after a network failure lands on the same PK and is dropped — no double-counting.
- RLS enabled, no anon policies.

## Config entities (checked-in TS, `apps/painbank/src/data/program.ts`)

```ts
type ExerciseId = 'pushups' | 'squats' | 'pullups' | 'situps';

type ExerciseSet = { exercise: ExerciseId; count: number };

type DayProgram =
  | { date: string /* YYYY-MM-DD */; kind: 'workout'; pushupsOnly: number; mixed: readonly ExerciseSet[] }
  | { date: string; kind: 'rest' };

const CHALLENGE: {
  name: string;
  slogan: string;          // "Pain is just weakness leaving your body."
  startDate: string;       // e.g. '2026-07-13'
  endDate: string;         // '2026-07-31'
  days: readonly DayProgram[];  // one per calendar date in range, Sydney-local
};
```

## Derived shapes (computed, never stored)

- **Day totals**: per (participant, day, exercise) — sum of entry counts, displayed clamped at ≥ 0.
- **Day completion**: complete ⇔ pushup total ≥ `pushupsOnly` OR every mixed exercise total ≥ its count. Push-up entries count toward both modes. Mode toggle is per-device UI state (localStorage), never sent to the server.
- **LeaderboardRow** (API response): `{ participantId, name, totalsByExercise, daysComplete, percentComplete, perDay: [{ day, state: 'complete' | 'partial' | 'rest' | 'future' | 'none' }] }` — aggregated in TypeScript from raw month entries; ranked by percentComplete, ties by total reps.

## Identity (browser)

- `localStorage['painbank:identity']` = versioned JSON `{ v: 1, id: uuid, name: string }`.
- Created on successful POST /api/participants only (a 409 never strands a half-identity).
- Adoption (new device): pick a participant from GET /api/participants → write their `{id, name}` locally.

## API contracts

| Route | Method | Body / Query | Response | Cache |
|---|---|---|---|---|
| `/api/participants` | GET | — | `{ participants: [{ id, name }] }` name-sorted | `s-maxage=30` |
| `/api/participants` | POST | `{ id, name }` | 201 `{ participant }` · 400 invalid · 409 duplicate name | `no-store` |
| `/api/entries` | POST | `{ id, participantId, day, exercise, count }` | 201 `{ entry }` (200 on idempotent replay) · 400 invalid/FK | `no-store` |
| `/api/leaderboard` | GET | — | `{ challenge: { name, slogan, startDate, endDate }, rows: LeaderboardRow[] }` | `s-maxage=15, stale-while-revalidate=60` |

Server-side validation on every write (the only authority): uuid shapes, name 1–24 trimmed chars, exercise ∈ that day's program (either mode), day is a workout day within [startDate, endDate], count integer in [−500, 500] \ {0}.
